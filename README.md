# Halting Problem – Finite Observation Demonstration

## 1. Purpose

This project is a small academic demonstration of the practical limitation of finite observation in the study of computation. It does not attempt to solve the Halting Problem.

The analyzer in this project is intentionally conservative. It observes whether a program terminates before a fixed timeout. If termination is observed, the result is reported as HALTS. If the timeout is reached first, the result is reported as UNKNOWN.

## 2. Project Structure

- analyzer.py — finite-observation analyzer
- run_experiments.py — main experiment runner
- test_cases/ — test programs used in the demonstration
- results/results.csv — CSV output generated by the runner
- README.md — academic description of the project

## 3. Requirements

- Python 3
- Only the Python standard library
- No external dependencies
- Windows-compatible subprocess handling

## 4. How to Run

From the project root, run:

python run_experiments.py

This will execute the six demonstration cases, print a digestible report, and overwrite the CSV file in the results directory.

## 5. Test Cases

The project includes six cases:

1. Immediate termination
2. Finite loop that completes quickly
3. Slow but terminating program that exceeds the 2-second timeout
4. Genuine infinite loop
5. Input-dependent program with input 1
6. Input-dependent program with input 0

## 6. Meaning of HALTS and UNKNOWN

HALTS:
Termination was directly observed before the timeout.

UNKNOWN:
Termination was not observed before the timeout.

UNKNOWN does not mean "does not halt." It means only that no termination was observed during the finite observation window.

## 7. Expected Results

With a 2.0-second timeout, the expected logical outcomes are:

- Case 1: HALTS
- Case 2: HALTS
- Case 3: UNKNOWN
- Case 4: UNKNOWN
- Case 5A (input = 1): HALTS
- Case 5B (input = 0): UNKNOWN

## 8. What This Experiment Demonstrates

This experiment illustrates a basic limitation of finite observation:

A fixed timeout can observe some terminating programs, but it cannot reliably distinguish all eventual halting programs from all non-halting programs.

If the timeout is increased from 2 seconds to 10 seconds, another program may still halt after 11 seconds, one hour, or any other arbitrarily large finite time. Therefore, no fixed finite timeout can decide all cases.

## 9. What This Experiment Does NOT Prove

This project does not solve the Halting Problem.

It also does not prove the undecidability result by itself. The formal proof of undecidability is established separately using theoretical arguments such as contradiction and self-reference.

This project only demonstrates the practical and conceptual limitation of observing computation with a finite time bound.

## 10. Summary

The analyzer is intentionally limited to finite observation. It reports the observable status only as HALTS or UNKNOWN. That is the correct experimental framing for this demonstration.
